# 🔐 Decentralized Escrow Platform

## Описание проекта

Это полнофункциональная децентрализованная платформа эскроу, построенная на базе Scaffold-ETH 2. Платформа позволяет безопасно проводить P2P транзакции между покупателями и продавцами с участием третьей стороны (арбитра) для разрешения споров.

## Основные возможности

### ✅ Функционал смарт-контракта

1. **Создание эскроу-сделок**
   - Покупатель создает сделку с блокировкой средств
   - Указывает продавца, арбитра и сумму
   - Средства надежно хранятся на контракте

2. **Жизненный цикл сделки**
   - `CREATED` → Сделка создана
   - `FUNDED` → Средства заблокированы
   - `DELIVERED` → Продавец подтвердил отправку
   - `COMPLETED` → Покупатель подтвердил получение, средства переведены
   - `DISPUTED` → Открыт спор, требуется вмешательство арбитра
   - `REFUNDED` → Средства возвращены покупателю
   - `CANCELLED` → Сделка отменена

3. **Подтверждение доставки**
   - Продавец отмечает отправку товара/услуги
   - Переводит статус сделки в `DELIVERED`

4. **Подтверждение получения**
   - Покупатель подтверждает получение
   - Автоматическое распределение средств:
     - 99% продавцу (за вычетом комиссии платформы 1%)
     - 1% платформе

5. **Система споров**
   - Покупатель или продавец может открыть спор
   - Арбитр принимает решение в пользу одной из сторон
   - Комиссия арбитра удерживается из суммы сделки

6. **Отмена сделки**
   - Возможна на стадии `FUNDED`
   - Полный возврат средств покупателю

7. **Вывод средств**
   - Безопасная система pending withdrawals
   - Защита от реентрантности

### 🎨 Функционал фронтенда

1. **Dashboard со статистикой**
   - Общее количество сделок
   - Суммарный объем транзакций
   - Баланс доступный к выводу

2. **Создание сделки**
   - Интуитивная форма с валидацией
   - Указание адресов участников
   - Настройка суммы и комиссии арбитра
   - Описание сделки

3. **Управление сделками**
   - Список всех сделок пользователя
   - Фильтрация по статусу
   - Визуальные индикаторы статуса
   - Контекстные действия в зависимости от роли

4. **Взаимодействие с контрактом**
   - Подтверждение доставки (продавец)
   - Подтверждение получения (покупатель)
   - Открытие спора
   - Отмена сделки
   - Вывод средств

## Архитектура контракта

### Безопасность

✅ **Реализованные меры безопасности:**

- **Checks-Effects-Interactions паттерн**: Изменения состояния перед внешними вызовами
- **Pull over Push**: Система pending withdrawals вместо прямых переводов
- **Модификаторы доступа**: Строгий контроль прав на выполнение функций
- **Защита от переполнения**: Solidity 0.8+ встроенная проверка
- **Валидация входных данных**: Проверка всех параметров
- **Защита от реентрантности**: Обнуление балансов перед переводами

### Газовая оптимизация

- Использование `immutable` для владельца контракта
- Эффективные структуры данных
- Минимизация операций хранения
- Использование событий вместо хранения логов

## Установка и запуск

### Предварительные требования

```bash
node >= 18.0.0
yarn >= 1.22.0
```

### Шаги установки

1. **Клонирование репозитория**
```bash
git clone <repository-url>
cd scaffold-eth-2
```

2. **Установка зависимостей**
```bash
yarn install
```

3. **Запуск локальной сети**
```bash
yarn chain
```

4. **Развертывание контрактов** (в новом терминале)
```bash
yarn deploy
```

5. **Запуск фронтенда** (в новом терминале)
```bash
yarn start
```

6. **Откройте приложение**
```
http://localhost:3000
```

## Использование

### Сценарий 1: Успешная сделка

1. **Покупатель** создает эскроу с суммой и адресами участников
2. **Продавец** получает уведомление и отправляет товар
3. **Продавец** подтверждает отправку через `confirmDelivery()`
4. **Покупатель** получает товар и подтверждает через `confirmReceipt()`
5. Средства автоматически распределяются
6. **Продавец** выводит средства через `withdraw()`

### Сценарий 2: Сделка со спором

1. **Покупатель** создает эскроу
2. **Продавец** подтверждает отправку
3. **Покупатель** не получает товар или товар не соответствует описанию
4. **Покупатель** открывает спор через `raiseDispute()`
5. **Арбитр** изучает доказательства обеих сторон
6. **Арбитр** принимает решение через `resolveDispute()`
7. Средства переводятся согласно решению

### Сценарий 3: Отмена сделки

1. **Покупатель** создает эскроу
2. Продавец не может выполнить обязательства
3. Стороны договариваются об отмене
4. Любая сторона вызывает `cancelEscrow()`
5. Средства возвращаются покупателю

## Экономика платформы

### Комиссии

- **Комиссия платформы**: 1% (регулируется владельцем, максимум 5%)
- **Комиссия арбитра**: Устанавливается при создании сделки (максимум 10% от суммы)

### Пример распределения средств

Для сделки на 1 ETH с комиссией арбитра 0.05 ETH:

**При успешном завершении:**
- Продавец: 0.99 ETH (1 ETH - 1%)
- Платформа: 0.01 ETH (1%)
- Арбитр: 0 ETH (не участвовал)

**При разрешении спора в пользу продавца:**
- Продавец: 0.9405 ETH ((1 - 0.05) * 0.99)
- Платформа: 0.0095 ETH ((1 - 0.05) * 0.01)
- Арбитр: 0.05 ETH (комиссия за работу)

**При разрешении спора в пользу покупателя:**
- Покупатель: 0.95 ETH (возврат минус комиссия арбитра)
- Арбитр: 0.05 ETH (комиссия за работу)
- Платформа: 0 ETH
